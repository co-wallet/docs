# Гайдлайн интерфейса co-wallet

## Общий каркас

Все routed-страницы сохраняют `IonPage → IonHeader / AppContent`. Навигация использует
`IonMenuButton` для корневых экранов и `IonBackButton` для вложенных. Не заменять
`IonPage`, `IonRouterOutlet` и Ionic-навигацию обычными контейнерами.

`AppContent` задаёт одну колонку шириной **до 768 px** для главной, списков, форм,
входа, приглашения и административных страниц. На узком экране колонка занимает
доступную ширину. Отступы — **16 px**, дополнительно учитываются safe area и место
под системный scrollbar. Симметричный `scrollbar-gutter` предотвращает изменение
ширины и смещение центра между короткими и длинными страницами.

Общий каркас применяется также к состояниям загрузки, пустого результата и ошибки.

Не задавать странице собственный `maxWidth`, `max-width`, `margin: auto` или второй
`ion-padding`. Ширина находится в `--app-content-width`, базовые отступы — в
`--app-page-gutter`; оба токена определены в `AppContent.css`. Панели заголовков
сохраняют фон на всю ширину, а их содержимое центрируется над общей колонкой.

```tsx
<IonPage>
  <IonHeader>
    <IonToolbar>
      <IonButtons slot="start"><IonMenuButton /></IonButtons>
      <IonTitle>Счета</IonTitle>
    </IonToolbar>
  </IonHeader>
  <AppContent
    withFab
    fixed={
      <IonFab slot="fixed" vertical="bottom" horizontal="end">
        <IonFabButton aria-label="Добавить счёт" onClick={openForm}>
          <IonIcon icon={addOutline} />
        </IonFabButton>
      </IonFab>
    }
  >
    <IonList>{/* строки */}</IonList>
  </AppContent>
</IonPage>
```

`fixed` передаёт FAB непосредственно в fixed slot `IonContent`, за пределами
прокручиваемого контейнера. `withFab` резервирует 104 px снизу, чтобы последний
элемент можно было прокрутить выше кнопки. При условном FAB передавать то же
условие в `withFab`. Обычная форма без FAB использует `<AppContent>`.

## Когда какой компонент использовать

| Задача | Компонент и правила |
| --- | --- |
| Повторяющиеся записи: счета, категории, теги, пользователи, валюты, приглашения | `IonList` + `IonItem`. Заголовок в `IonLabel`, пояснение в `p`, значение в `IonNote slot="end"`. У списка нет дополнительного `inset`: отступ задаёт каркас. |
| Группы полей | `IonList`, при необходимости `IonListHeader`; промежуток между секциями 16 px. |
| Сводка, график, самостоятельный блок или переход в раздел | `IonCard`, `IonCardHeader/Title/Content`. Общий радиус 12 px, заголовок 18 px / 600. Карточки в локальной сетке могут обнулить внешние отступы, используя `gap` сетки. |
| Ввод текста, суммы, даты | `IonInput` / `IonTextarea` с видимым `label` и `labelPlacement="stacked"`. Подсказка не заменяет подпись. Сохранять `inputMode`, autocomplete и точность денежных значений. |
| Выбор значения из короткого списка | `IonSelect`; для счета и категории — `AccountSelect` / `CategorySelect`, чтобы сохранить общий вид иконок и списков. |
| Переключение раздела одного экрана | `IonSegment`, как расходы/доходы категорий. |
| Переключатель настройки | `IonToggle` с понятной подписью в строке. |
| Основное создание в списке | Один FAB с доступным названием. Не дублировать его рядом второй основной кнопкой. |
| Сохранение формы | `IonButton expand="block"`, высота от 44 px; disabled при отправке или невалидных данных, spinner на время запроса. В редакторах с действием в toolbar сохраняется toolbar-кнопка. |
| Вторичное действие | `IonButton fill="clear"` или `fill="outline"`; кнопке только с иконкой нужен `aria-label`. |
| Действия над строкой | В справочниках категорий и тегов — видимые кнопки `IonButton` внутри `IonButtons`: скрытие, редактирование и удаление. У тега отдельная ссылка «Операции» открывает историю. Удаление — `danger` и подтверждение в `IonAlert`. |
| Небольшой редактор | `IonModal` с header и `AppContent`. Ширина ограничена самим Ionic modal; внутри действуют те же отступы и поля. |
| Фильтрация нескольких параметров | Общий `FilterSheet`; фильтры остаются в sheet, выбранный период — на странице. |
| Статус приглашения или записи | `IonBadge` с текстом; цвет дополняет текст, а не заменяет его. |

## Состояния и темы

- Загрузка и пустой результат используют `.app-state`: центрирование, промежуток
  12 px, отступы 48 × 16 px, иконка 40 px. Длинный список транзакций сохраняет
  skeleton-строки, чтобы показывать структуру будущего результата.
- Ошибка запроса не должна менять ширину страницы. Для ошибки с повтором загрузки
  использовать `.app-state`, `role="alert"` и кнопку повтора. Ошибка поля или
  сохранения остаётся рядом с соответствующей формой в `IonText color="danger"`.
- Основной текст использует `--ion-text-color`, пояснения — тематические Ionic
  цвета. Денежные суммы используют существующие semantic tokens транзакций.
  Иконки счетов и категорий — только через общие компоненты.
- Светлая, тёмная и системная темы управляются `themeStore`. Цвета графиков брать
  из общего chart helper. Не добавлять локальное определение темы страницы.
- Специальные элементы остаются специальными: список категорий, таблица долей,
  календарь, график и сводка транзакций сохраняют свою структуру внутри общего
  каркаса. Не превращать каждую строку в отдельную карточку.

## Проверка новой страницы

Запустить `npm run test`, `npm run lint`, `npm run build`. В браузере проверить
ширины 320/390, 768 и 1440 px, светлую и тёмную темы, загрузку, пустой результат,
ошибку и заполненный список. Убедиться, что нет горизонтальной прокрутки,
модальное окно помещается в экран, а последняя строка доступна над FAB.

Для воспроизводимой проверки без доступа к API используйте
[тестовый стенд frontend](https://github.com/co-wallet/frontend/blob/main/tests/layout/README.md).
